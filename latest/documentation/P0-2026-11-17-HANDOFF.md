## What changed and why

- File-specific 120-second media leases renew via authenticated control requests every 45 seconds. Their continuation survives broad-session expiry/adapter renewal and uses the same URL/player. Explicit root revocation still invalidates leases and per-chunk reads; no general bearer enters URLs. Exact Origin, Host and guarded-file checks remain enforced.
- Active Shelf playback is pinned independently of directory state, selection, thumbnails and ordinary previews. Stop/Close releases its lease. Browser decoding remains responsible for supported codecs; no transcoding is promised.
- Original GET diagnostics precede HEAD diagnoses. An HTTP 403 alone no longer claims the user revoked their folder. Error categories distinguish expiry, authorization, changed source, busy lanes, codec/decode and disconnect.
- Independent bounded control/navigation/preview/thumbnail/media/intake lanes, a global 32-thread ceiling, small streaming chunks and hardware-aware presets avoid a shared thumbnail bottleneck. Stale list/search requests cancel, pending search timers cannot override later folder clicks, and coalesced view-state persistence does not block rendering. Transfer journal fsync does not hold the status lock.
- Folder Access uses the browser top layer; image/background clicks establish preview focus without stealing editable/media keys. First-use Open/Reveal defaults to system apps; existing explicit preferences survive. Settings and toolbar Popup/Shelf behavior share supported Chrome APIs.
- Clipboard operations use a separate versioned native module and the same guarded file identities. Windows clipboard snapshots authorize only specific resolved files for paste, not a new browsable filesystem scope.
